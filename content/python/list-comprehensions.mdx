# 1. Introduction & Real Production Problem Statement

## Why Python Iteration Syntax Matters
Python provides concise, readable syntax for creating collections from iterables. **List Comprehensions** provide a functional, high-performance alternative to traditional `for` loops by executing loop operations in C-speed bytecode (`LIST_APPEND`).

---

# 2. Core Concepts & Mental Model

## 1. Syntax Anatomy
$$\text{result} = [\text{expression} \text{ for } \text{item} \text{ in } \text{iterable} \text{ if } \text{condition}]$$

## 2. Generator Expressions vs List Comprehensions

```python
# List Comprehension: Allocates full list in memory immediately [O(N) RAM]
numbers_list = [x * 2 for x in range(1000000)]

# Generator Expression: Evaluates values lazily on demand [O(1) RAM]
numbers_gen = (x * 2 for x in range(1000000))
```

## 3. Senior Engineer Explanation & CPython Bytecode
Using Python's `dis` module reveals that CPython compiles list comprehensions into dedicated `BUILD_LIST` and `LIST_APPEND` opcodes. This avoids Python-level method lookup overhead (`list.append()`), running loop operations directly inside CPython's C runtime.

# 3. Code Examples & Refactoring Patterns

## Bad Code: Verbose Loop with Method Lookup Overhead

```python
# BAD: Repeated attribute lookup `results.append` slows down execution
def get_even_squares_naive(numbers: list[int]) -> list[int]:
    results = []
    for num in numbers:
        if num % 2 == 0:
            results.append(num ** 2)
    return results
```

## Refactored Enterprise Code: High-Performance Comprehension

```python
# GOOD: Clean, C-speed bytecode execution
def get_even_squares_optimized(numbers: list[int]) -> list[int]:
    return [num ** 2 for num in numbers if num % 2 == 0]
```

# 4. Debugging Guide & Common Mistakes

## Fixing Memory Exhaustion on Massive Data Sets

```python
# BUG: Loading 50 Million records into memory causes MemoryError
def process_large_log_file(filepath: str) -> int:
    with open(filepath) as f:
        # Crashes server if file is 10 GB!
        error_lines = [line for line in f if "ERROR" in line] 
    return len(error_lines)

# FIX: Stream data lazily using generator expression
def process_large_log_file_optimized(filepath: str) -> int:
    with open(filepath) as f:
        error_lines = (line for line in f if "ERROR" in line)
        return sum(1 for _ in error_lines) # O(1) memory usage!
```

# 5. Performance & Security Notes

## Performance Notes
- **Memory Footprint**: Use Generator Expressions `(x for x in data)` when chaining multi-stage ETL data pipelines to process streaming data without RAM bottlenecks.

## Security Notes
- **Avoid Dynamic `eval()`**: Never evaluate untrusted string input inside comprehension expressions.

# 6. Interview Questions & Practice Exercises

### Q1: Compare List Comprehension vs `map()` with `lambda`.
- *Answer*: List comprehensions are generally more readable and faster in Python 3 because `map()` with a lambda incurs function call overhead per item.

### Q2: What is the space complexity of a Generator Expression?
- *Answer*: $O(1)$ constant space because values are computed lazily on demand using the iterator protocol (`__next__()`).
