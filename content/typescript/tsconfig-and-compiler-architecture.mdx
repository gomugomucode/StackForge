# 1. Introduction

## Why Compiler Architecture & tsconfig Tuning Matter
In enterprise applications, misconfigured TypeScript setups cause slow build times (30s+ type-check delays), hidden runtime crashes due to weak type flags, and broken monorepo package boundary resolution. Understanding the **TypeScript Compiler (`tsc`) Pipeline** and mastering `tsconfig.json` hardening is critical for maintaining high velocity in large developer teams.

# 2. Core Concepts

## The TypeScript Compiler (`tsc`) Pipeline

```
+------------------+
| TS Source Code   |
+------------------+
         |
         v
+------------------+
| Scanner / Lexer  | --> Converts text into Token stream
+------------------+
         |
         v
+------------------+
|     Parser       | --> Converts Tokens into Abstract Syntax Tree (AST)
+------------------+
         |
         v
+------------------+
|     Binder       | --> Links AST Nodes into Symbols and creates Symbol Table
+------------------+
         |
         v
+------------------+
|    Checker       | --> Validates type rules & emits TS Diagnostic Errors
+------------------+
         |
         v
+------------------+
|    Emitter       | --> Strips types and generates JS code & .d.ts files
+------------------+
```

# 3. Production `tsconfig.json` Hardened Reference

```json
{
  "compilerOptions": {
    /* Target & Modules */
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "lib": ["ES2022"],
    
    /* Strict Type-Checking Hardening */
    "strict": true,
    "noImplicitAny": true,
    "strictNullChecks": true,
    "strictFunctionTypes": true,
    "strictBindCallApply": true,
    "strictPropertyInitialization": true,
    "noImplicitThis": true,
    "useUnknownInCatchVariables": true,
    "alwaysStrict": true,
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": true,

    /* Code Quality & Linter Checks */
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noImplicitReturns": true,
    "noFallthroughCasesInSwitch": true,
    "noImplicitOverride": true,

    /* Output & Monorepo Build Optimization */
    "declaration": true,
    "declarationMap": true,
    "sourceMap": true,
    "composite": true,
    "incremental": true,
    "skipLibCheck": true,
    "isolatedModules": true
  }
}
```

# 4. Interview Questions

### Easy Questions
1. **Q: What is `tsc`?**
   - *Answer*: The official TypeScript Compiler executable that parses, type-checks, and emits JavaScript.
2. **Q: What does `"strict": true` do in `tsconfig.json`?**
   - *Answer*: Enables a family of strict type-checking flags including `noImplicitAny`, `strictNullChecks`, and `strictFunctionTypes`.
3. **Q: What is a `.d.ts` file?**
   - *Answer*: A declaration file containing only TypeScript type information without runtime JavaScript code implementation.
4. **Q: What does `skipLibCheck` do?**
   - *Answer*: Skips type checking of declaration files (`.d.ts`) in `node_modules`, dramatically speeding up compilation.
5. **Q: What is `isolatedModules` flag used for?**
   - *Answer*: Warns if code relies on single-file transpilers (like Babel, SWC, esbuild) failing (e.g. re-exporting types without `export type`).

### Medium Questions
6. **Q: Explain Project References in TypeScript.**
   - *Answer*: A `tsconfig` feature allowing large monorepo codebases to be split into separate logical sub-projects compiled incrementally.
7. **Q: What is the Binder phase in the compiler pipeline?**
   - *Answer*: The phase that inspects AST nodes, creates `Symbol` entries, and links identifiers across scope chains.
8. **Q: How does `noUncheckedIndexedAccess` improve security?**
   - *Answer*: Forces array and record index accesses (e.g. `arr[i]`) to include `undefined` in their type, preventing unchecked property access on undefined.
9. **Q: What is ambient declaration (`declare module`)?**
   - *Answer*: Tells TypeScript about untyped external JavaScript packages or global variables without providing implementation.
10. **Q: Compare `moduleResolution: "node"` vs `"NodeNext"`.**
    - *Answer*: `"node"` uses legacy CommonJS resolution; `"NodeNext"` supports modern Node.js native ESM package exports/imports and file extensions (`.js`, `.mjs`).

### Advanced Questions
11. **Q: Walk through the 5 phases of the TypeScript compiler execution.**
    - *Answer*: 1. Scanner (tokenization) $\rightarrow$ 2. Parser (AST construction) $\rightarrow$ 3. Binder (Symbol table creation) $\rightarrow$ 4. Checker (type rule verification & diagnostic collection) $\rightarrow$ 5. Emitter (JavaScript code & `.d.ts` generation).
12. **Q: How do `exactOptionalPropertyTypes` and standard optional properties differ?**
    - *Answer*: Standard `foo?: string` allows assigning `undefined` explicitly (`{ foo: undefined }`); `exactOptionalPropertyTypes` disallows explicit `undefined` assignments unless `undefined` is in the union type.
13. **Q: How do you optimize `tsc` build times in a 100k+ LOC monorepo?**
    - *Answer*: Enable `"composite": true`, `"incremental": true`, `"skipLibCheck": true`, use Project References (`tsc --build`), and avoid heavy conditional recursive types.
14. **Q: What is the purpose of `declarationMap`?**
    - *Answer*: Emits source maps for `.d.ts` declaration files, allowing IDEs ("Go to Definition") to jump directly to TypeScript source files in monorepos rather than compiled `.d.ts` files.
15. **Q: How does `tsc` handle Module Augmentation?**
    - *Answer*: Merges new property declarations into existing module interfaces using ambient `declare module "package-name"` blocks.
