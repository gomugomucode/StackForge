# 1. Introduction

## Why Hooks Internals Matter
React Hooks (`useState`, `useEffect`, `useCallback`, `useRef`) transformed how state and side-effects are structured. However, without understanding how hooks work under the hood (linked lists on Fiber nodes, closure trapping, dependency array equality checks), developers frequently trigger **stale closure bugs**, **infinite render loops**, and **unnecessary re-renders**.

---

# 2. Core Concepts

## How Hooks are Stored: Fiber Linked List
Hooks do not rely on magic; they are stored as a **singly linked list** attached directly to the active Fiber node's `memoizedState` property.

```
FiberNode.memoizedState
       |
       v
+------------------+     next     +------------------+     next     +------------------+
| Hook 1: useState | ------------>| Hook 2: useEffect| ------------>| Hook 3: useRef   |
| (count = 0)      |              | (deps: [count])  |              | (ref.current)    |
+------------------+              +------------------+              +------------------+
```

### The Rules of Hooks Explained
This linked list architecture is precisely why **Hooks must always be called in the exact same order at the top level of a component**:
- If a hook call is wrapped inside an `if` condition or loop, the index in the linked list shifts on subsequent renders, causing React to mismatch state values across hooks and throw errors!

# 3. Code Examples

## Production: Custom Resilient Data Fetching Hook with Cancellation & Retry

```typescript
import { useState, useEffect, useCallback, useRef } from "react";

export interface FetchState<T> {
  data: T | null;
  loading: boolean;
  error: Error | null;
}

export function useFetch<T>(url: string, options?: RequestInit) {
  const [state, setState] = useState<FetchState<T>>({
    data: null,
    loading: true,
    error: null,
  });

  const optionsRef = useRef(options);
  optionsRef.current = options;

  const execute = useCallback(async () => {
    const controller = new AbortController();
    setState((prev) => ({ ...prev, loading: true, error: null }));

    try {
      const res = await fetch(url, {
        ...optionsRef.current,
        signal: controller.signal,
      });

      if (!res.ok) throw new Error(`HTTP ${res.status}: ${res.statusText}`);
      const data = (await res.json()) as T;

      setState({ data, loading: false, error: null });
    } catch (err: any) {
      if (err.name !== "AbortError") {
        setState({ data: null, loading: false, error: err });
      }
    }

    return () => controller.abort();
  }, [url]);

  useEffect(() => {
    const cleanupPromise = execute();
    return () => {
      cleanupPromise.then((cleanup) => cleanup && cleanup());
    };
  }, [execute]);

  return { ...state, refetch: execute };
}
```

# 4. Interview Questions

### Easy Questions
1. **Q: What are React Hooks?**
   - *Answer*: Functions allowing functional components to hook into React state and lifecycle features.
2. **Q: Why can't hooks be called inside conditional statements?**
   - *Answer*: React tracks hooks via a strict ordered linked list attached to the Fiber node. Changing order breaks list matching.
3. **Q: What is the difference between `useState` and `useRef`?**
   - *Answer*: `useState` triggers a component re-render when state changes; `useRef` returns a mutable object that persists across renders without triggering a re-render.
4. **Q: When does `useEffect` cleanup run?**
   - *Answer*: Before the component unmounts and before re-running the effect on subsequent dependency changes.
5. **Q: What is `useCallback` used for?**
   - *Answer*: Memoizes function instances across renders to prevent unnecessary re-renders of child components wrapped in `React.memo`.

### Medium Questions
6. **Q: Explain Stale Closures in React Hooks.**
   - *Answer*: Occurs when an effect or callback captures state/props variables from an earlier render cycle because dependency arrays were omitted or incomplete.
7. **Q: How does `useReducer` compare to `useState`?**
   - *Answer*: `useState` is built on top of `useReducer`; `useReducer` is preferred for complex state logic with multiple sub-values or next-state dependency actions.
8. **Q: Compare Context API vs Zustand for global state.**
   - *Answer*: Context triggers re-renders on ALL consuming components whenever any value in the context object changes (lacks selector support); Zustand supports atomic state selection and outside-React state access.
9. **Q: What is `useId` hook used for?**
   - *Answer*: Generates unique, stable IDs across server and client renders to prevent SSR hydration mismatch errors in accessible form controls.
10. **Q: What is the purpose of `useImperativeHandle`?**
    - *Answer*: Customizes the instance value exposed to parent components when using `ref`.

### Advanced Questions
11. **Q: Walk through how React tracks `useState` setters under the hood.**
    - *Answer*: Calling `setState(action)` enqueues an update object onto the hook's update queue on the Fiber node and schedules a Fiber render workloop at the assigned Lane priority.
12. **Q: How do atomic state managers (Jotai/Recoil) prevent top-down re-renders compared to Redux?**
    - *Answer*: Atomic state managers treat state as an implicit graph of atoms; components subscribe directly to individual atom signals, causing isolated re-renders without traversing a global root store.
13. **Q: How would you debug an infinite render loop caused by `useEffect`?**
    - *Answer*: Inspect dependency arrays for newly instantiated object/array literals or un-memoized callbacks passed from parent props.
14. **Q: What is `useSyncExternalStore` and why was it introduced in React 18?**
    - *Answer*: A hook for subscribing to external non-React data stores safely under Concurrent Mode without tearing (inconsistent UI reads during non-blocking renders).
15. **Q: How does React perform dependency array comparison in `useEffect`?**
    - *Answer*: Uses `Object.is()` comparison sequentially across each element in the dependency array.
