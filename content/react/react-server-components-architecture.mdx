# 1. Introduction

## Why React Server Components Matter
Traditionally, Single Page Applications (SPAs) downloaded massive JavaScript bundles to the browser to fetch data and render UI client-side, causing slow Initial Page Load times and large bundle sizes. Traditional Server-Side Rendering (SSR) generated static HTML on the server, but required full client-side hydration of the entire component tree before becoming interactive.

**React Server Components (RSC)** introduce a paradigm shift: components that execute **exclusively on the server**, outputting a lightweight streaming JSON payload (the Flight Protocol) with **zero client-side JavaScript bundle cost**.

# 2. Core Concepts

## RSC vs Client Components Matrix

| Feature | Server Components (Default) | Client Components (`'use client'`) |
| :--- | :--- | :--- |
| **Execution Environment** | Server Only | Server (SSR) + Client (Browser) |
| **Bundle Size Impact** | 0 KB JavaScript sent to browser | Included in Client JS Bundle |
| **Database Access** | Direct access to DB, File System, Secrets | Cannot access DB directly (Must fetch via API/Action) |
| **React Hooks (`useState`, `useEffect`)** | ❌ Not Allowed | ✅ Supported |
| **Event Handlers (`onClick`)** | ❌ Not Allowed | ✅ Supported |

## Flight Protocol & Streaming SSR

```
+--------------------------------------------------------------+
| SERVER (Node.js / Edge Runtime)                              |
|  1. Fetches DB directly inside Server Component              |
|  2. Serializes UI tree into Flight Spec (JSON Stream)        |
+--------------------------------------------------------------+
                              |
                              | HTTP Chunked Streaming (ReadableStream)
                              v
+--------------------------------------------------------------+
| CLIENT (Browser)                                             |
|  1. Receives Flight Stream chunk-by-chunk                    |
|  2. Reconciliation Engine reconstructs Virtual DOM           |
|  3. Hydrates ONLY 'use client' components dynamically        |
+--------------------------------------------------------------+
```

# 3. Code Examples

## Production: Server Component Data Fetching with Suspense & Server Action

```tsx
// Server Component (Default - No 'use client' directive)
import { Suspense } from "react";
import { db } from "@/lib/db";
import { revalidatePath } from "next/cache";

async function UserProfile({ userId }: { userId: string }) {
  // Direct async database access without API endpoints or client state!
  const user = await db.user.findUnique({ where: { id: userId } });
  if (!user) return <div>User not found</div>;

  return (
    <div className="p-4 border rounded">
      <h2 className="text-xl font-bold">{user.name}</h2>
      <p>Email: {user.email}</p>
    </div>
  );
}

// Server Action for mutation
async function updateUserEmail(formData: FormData) {
  "use server";
  const userId = formData.get("userId") as string;
  const newEmail = formData.get("email") as string;

  await db.user.update({
    where: { id: userId },
    data: { email: newEmail },
  });

  revalidatePath("/dashboard");
}

export default async function DashboardPage() {
  return (
    <div className="space-y-6">
      <h1>Developer Dashboard</h1>

      {/* Streaming SSR with Suspense Boundary */}
      <Suspense fallback={<div>Loading profile from DB...</div>}>
        <UserProfile userId="user_123" />
      </Suspense>

      {/* Form calling Server Action */}
      <form action={updateUserEmail} className="space-y-2">
        <input type="hidden" name="userId" value="user_123" />
        <input type="email" name="email" placeholder="New Email" required className="border p-2" />
        <button type="submit" className="bg-blue-600 text-white px-4 py-2 rounded">
          Update Email
        </button>
      </form>
    </div>
  );
}
```

# 4. Interview Questions

### Beginner Questions
1. **Q: What is a React Server Component (RSC)?**
   - *Answer*: A component that executes exclusively on the server, rendering zero client-side JavaScript bundle code to the browser.
2. **Q: What does `'use client'` directive mean?**
   - *Answer*: Marks the boundary between Server-only code and Client-interactive components requiring browser JS hydration and hooks.
3. **Q: Can Server Components use `useState` or `useEffect`?**
   - *Answer*: No, state and side-effect hooks require browser DOM runtime environments.
4. **Q: Can you import a Server Component into a Client Component?**
   - *Answer*: Not directly via standard imports, but you can pass Server Components as `children` props into Client Components.
5. **Q: What is a Server Action (`'use server'`)?**
   - *Answer*: An async server function that can be called from client forms or events to execute server mutations directly.

### Medium Questions
6. **Q: What is the Flight Protocol?**
   - *Answer*: A binary/JSON-like string format used by RSC to stream rendered component trees, props, and client module references from server to client.
7. **Q: How does RSC differ from traditional SSR?**
   - *Answer*: Traditional SSR generates HTML and requires downloading all component JS for full hydration; RSC streams serialized component ASTs with zero JS bundle overhead for server nodes.
8. **Q: What is Selective Hydration in React 18+?**
   - *Answer*: Streaming HTML inside `<Suspense>` boundaries allows early-loaded page sections to hydrate and become interactive before slower fallback sections finish downloading.
9. **Q: How do you pass data from a Server Component to a Client Component?**
   - *Answer*: Pass serializable props (strings, numbers, objects, arrays, plain JSON); non-serializable values (functions, symbols) cannot cross the boundary.
10. **Q: What security precaution must be taken with Server Actions?**
    - *Answer*: Always validate user authorization and sanitize inputs inside Server Actions, treating them with the same security rigor as public POST API endpoints.

### Advanced Questions
11. **Q: Walk through how React handles a `'use client'` module reference in the Flight stream.**
    - *Answer*: The server emits a manifest token `$Sclient_id` pointing to the client bundle chunk URL. Upon streaming to the browser, React dynamically loads the module and hydrates the subtree.
12. **Q: How does `server-only` package protect against credential leaks?**
    - *Answer*: Importing `import 'server-only'` throws a build error if the module is accidentally imported into any client boundary file.
13. **Q: Why can Server Components be passed as `children` to Client Components without becoming Client Components?**
    - *Answer*: The Server Component is executed on the server *before* being passed as a pre-rendered Flight element prop into the Client Component container.
14. **Q: How do Server Actions integrate with optimistic UI updates in React 19?**
    - *Answer*: React 19 provides `useOptimistic` hook allowing client UI to immediately reflect expected changes while the Server Action completes in the background.
15. **Q: Compare RSC performance vs traditional REST/GraphQL API fetching.**
    - *Answer*: RSC eliminates client-server network waterfalls by executing data fetching directly co-located on high-speed datacenter database networks before streaming results.
