# 1. Introduction & Real Production Problem Statement

## Why Asymptotic Analysis Matters
Writing code that works for $N = 100$ items is easy. Writing software that scales reliably when $N = 100,000,000$ requires mastering **Asymptotic Analysis (Big-O Notation)**. An $O(N^2)$ nested loop executing against a database table with 1M rows causes system downtime and CPU exhaustion.

---

# 2. Core Concepts & Mental Model

## 1. Mathematical Definitions
- **Big-O ($O$)**: Upper bound asymptote (Worst-case complexity).
- **Big-Omega ($\Omega$)**: Lower bound asymptote (Best-case complexity).
- **Big-Theta ($\Theta$)**: Tight bound asymptote (Exact complexity).

## 2. Common Complexity Classes Matrix

| Complexity Class | Name | Example Algorithm / Operation | Scalability Score |
| :--- | :--- | :--- | :---: |
| **$O(1)$** | Constant | Array lookup by index, Map `.get()` hash lookup | 🚀 Excellent |
| **$O(\log N)$** | Logarithmic | Binary search in sorted array, B-Tree index lookup | 🚀 Excellent |
| **$O(N)$** | Linear | Single loop array traversal, Linear search | ✅ Good |
| **$O(N \log N)$** | Linearithmic | Merge Sort, Quick Sort (avg), Heap Sort | ✅ Good |
| **$O(N^2)$** | Quadratic | Nested loops over input array, Bubble Sort | ⚠️ Avoid for Large N |
| **$O(2^N)$** | Exponential | Naive recursive Fibonacci without memoization | ❌ Unusable for N > 30 |

# 3. Code Examples & Performance Refactoring

## Bad Code: $O(N^2)$ Duplicate Array Search

```typescript
// BAD: O(N^2) time complexity due to nested indexOf call inside loop
export function findDuplicatesNaive(arr: number[]): number[] {
  const duplicates: number[] = [];
  for (let i = 0; i < arr.length; i++) {
    // indexOf performs an O(N) scan inside O(N) loop!
    if (arr.indexOf(arr[i]) !== i && !duplicates.includes(arr[i])) {
      duplicates.push(arr[i]);
    }
  }
  return duplicates;
}
```

## Refactored Enterprise Code: $O(N)$ Hash Set Implementation

```typescript
// GOOD: O(N) time complexity using Set O(1) lookups
export function findDuplicatesOptimized(arr: number[]): number[] {
  const seen = new Set<number>();
  const duplicates = new Set<number>();

  for (const item of arr) {
    if (seen.has(item)) {
      duplicates.add(item);
    } else {
      seen.add(item);
    }
  }

  return Array.from(duplicates);
}
```

# 4. Debugging Guide & Common Mistakes

## Debugging Call Stack Memory Leaks in Recursion ($O(N)$ Space)

```typescript
// BUG: Naive recursion allocates O(N) stack frames on Call Stack
function sumToN(n: number): number {
  if (n <= 1) return 1;
  return n + sumToN(n - 1); // Crash: RangeError: Maximum call stack size exceeded for N=100000
}

// FIX: Iterative algorithm with O(1) space complexity
function sumToNOptimized(n: number): number {
  return (n * (n + 1)) / 2; // O(1) time, O(1) space!
}
```

# 5. Performance & Security Notes

## Performance Notes
- **Space-Time Trade-off**: Improving time complexity from $O(N^2) \rightarrow O(N)$ often requires trading additional RAM space (e.g. Hash Maps, Caching).

## Security Notes
- **Algorithmic Complexity Attacks (ReDoS)**: Insecure Regular Expressions with backtracking cause $O(2^N)$ exponential CPU execution times, enabling Denial of Service (DoS) exploits.

# 6. Interview Questions & Practice Exercises

### Q1: What is the average vs worst-case time complexity of QuickSort?
- *Answer*: Average case is $O(N \log N)$; worst-case is $O(N^2)$ occurring when chosen pivots are consistently extreme elements (solved using randomized pivot selection).

### Q2: What is the space complexity of Depth-First Search (DFS) on a binary tree?
- *Answer*: $O(H)$ where $H$ is the height of the tree, representing max call stack recursion depth.
