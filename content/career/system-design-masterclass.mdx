# 1. Introduction

## Why System Design Architecture Matters
System Design is the art and science of defining the architecture, modules, interfaces, and data of a system to satisfy specified requirements at enterprise scale (millions of concurrent users, petabytes of storage, 99.999% availability).

# 2. Core Concepts

## CAP & PACELC Theorem Matrix

```
                      +-------------------+
                      |   CAP THEOREM     |
                      +-------------------+
                       /        |        \
                      /         |         \
         +---------------+ +---------------+ +---------------+
         |  CONSISTENCY  | | AVAILABILITY  | |  PARTITION    |
         | (Strong Read) | | (No Failures) | |  TOLERANCE    |
         +---------------+ +---------------+ +---------------+

PACELC Theorem Extension:
If there is a Partition (P), trade off Availability (A) vs Consistency (C);
Else (E), trade off Latency (L) vs Consistency (C).
```

## Distributed Caching Strategies

| Strategy | Description | Read Latency | Cache Miss Cost | Data Freshness |
| :--- | :--- | :--- | :--- | :--- |
| **Cache-Aside (Lazy Loading)** | Application queries cache first; on miss, loads from DB & populates cache | Fast on Hit | High (Adds DB latency) | Stale until TTL/Invalidation |
| **Read-Through** | Application queries cache; cache middleware transparently fetches from DB | Fast | Medium | Always in sync |
| **Write-Through** | Writes to cache and DB synchronously in same transaction | Slower Writes | None | Guaranteed Fresh |
| **Write-Behind (Write-Back)** | Writes to cache instantly; async worker flushes to DB in background | Fastest Writes | Risk of data loss on crash | Eventually Consistent |

# 3. Code Examples

## Production: Consistent Hashing Ring Implementation

```typescript
import crypto from "node:crypto";

export class ConsistentHashRing {
  private ring: Map<number, string> = new Map();
  private sortedKeys: number[] = [];

  constructor(private replicaCount: number = 100) {}

  private hash(key: string): number {
    const hash = crypto.createHash("md5").update(key).digest("hex");
    return parseInt(hash.substring(0, 8), 16);
  }

  public addNode(node: string) {
    for (let i = 0; i < this.replicaCount; i++) {
      const virtualNodeKey = `${node}-replica-${i}`;
      const hash = this.hash(virtualNodeKey);
      this.ring.set(hash, node);
      this.sortedKeys.push(hash);
    }
    this.sortedKeys.sort((a, b) => a - b);
  }

  public getNode(key: string): string | null {
    if (this.ring.size === 0) return null;
    const hash = this.hash(key);

    // Binary search for first virtual node >= hash
    let low = 0;
    let high = this.sortedKeys.length - 1;

    while (low <= high) {
      const mid = Math.floor((low + high) / 2);
      if (this.sortedKeys[mid] >= hash) {
        high = mid - 1;
      } else {
        low = mid + 1;
      }
    }

    const index = low % this.sortedKeys.length;
    return this.ring.get(this.sortedKeys[index]) || null;
  }
}
```

# 4. Interview Database

### Question 1: How would you design a URL Shortener like Bit.ly?
- **Answer**: Use base62 encoding (`[a-zA-Z0-9]`) on a 64-bit auto-incrementing ID generated by a distributed ID generator (Snowflake). Cache hot mappings in Redis (`Cache-Aside`), write to MongoDB or PostgreSQL with unique index on short key.

### Question 2: How would you design a Distributed Rate Limiter for 10M requests/sec?
- **Answer**: Deploy Redis cluster running atomic Lua scripts executing Token Bucket or Sliding Window Counter algorithms. Use local in-memory L1 cache (LRFU) at gateway for ultra-fast rejecting before touching Redis L2.

### Question 3: How would you design a Real-time Messaging App like WhatsApp?
- **Answer**: Maintain persistent WebSockets via Netty/Node.js gateway nodes, use Cassandra/ScyllaDB for chat message history storage (partition key: `chat_id`, clustering key: `message_id`), use Kafka for offline message delivery queues, and WebRTC for P2P video calls.

### Question 4: How would you design a Video Streaming Service like Netflix?
- **Answer**: Upload raw video $\rightarrow$ triggers S3 event $\rightarrow$ Kafka queue $\rightarrow$ microservice transcoding workers split video into multi-resolution HLS/DASH chunks $\rightarrow$ push chunks to global CDN edge nodes (Cloudfront/Fastly) $\rightarrow$ client dynamically adapts bitrate based on bandwidth.

### Question 5: Compare Kafka vs RabbitMQ.
- **Answer**: Kafka is a distributed append-only commit log optimized for high-throughput replayable event streams; RabbitMQ is a message broker (AMQP) supporting complex routing (exchanges) and per-message acknowledgments.
