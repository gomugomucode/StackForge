# 1. Introduction

## Why Prisma ORM Architecture Matters
Traditional Node.js ORMs (Sequelize, TypeORM) often suffer from weak TypeScript integration, fragile string-based query builders, and unpredictable N+1 query patterns.

**Prisma** takes a fundamentally different architectural approach: a declarative schema (`schema.prisma`), an auto-generated type-safe client, and a high-performance **Rust Query Engine binary**.

# 3. Code Examples

## Production: Interactive Transaction with Atomic Rollback

```typescript
import { prisma } from "@/lib/prisma";

export async function transferCredits(senderId: string, recipientId: string, amount: number) {
  // Interactive transaction ensures atomic execution & rollback on error
  return await prisma.$transaction(async (tx) => {
    // 1. Decrement sender balance with check
    const sender = await tx.user.update({
      where: { id: senderId },
      data: { credits: { decrement: amount } },
    });

    if (sender.credits < 0) {
      throw new Error(`Insufficient credits for sender ${senderId}`);
    }

    // 2. Increment recipient balance
    const recipient = await tx.user.update({
      where: { id: recipientId },
      data: { credits: { increment: amount } },
    });

    // 3. Log audit record
    const log = await tx.creditTransaction.create({
      data: {
        senderId,
        recipientId,
        amount,
      },
    });

    return { sender, recipient, log };
  }, {
    maxWait: 5000, // Wait max 5s for connection from pool
    timeout: 10000, // Transaction must complete within 10s
  });
}
```

# 4. Interview Questions

### Easy Questions
1. **Q: What is Prisma ORM?**
   - *Answer*: A modern, type-safe ORM for Node.js and TypeScript featuring declarative schema modeling and auto-generated TypeScript client.
2. **Q: What is `schema.prisma`?**
   - *Answer*: The single source of truth configuration file defining database models, relations, datasources, and client generators.
3. **Q: What is the difference between `prisma migrate dev` and `prisma migrate deploy`?**
   - *Answer*: `migrate dev` creates new SQL migration files and updates local dev database; `migrate deploy` executes pending migrations against production databases without creating new files.
4. **Q: How do you define a 1-to-Many relation in Prisma?**
   - *Answer*: Define array relation field on parent model (e.g. `posts Post[]`) and reference field with `@relation` on child model (e.g. `author User @relation(fields: [authorId], references: [id])`).
5. **Q: What is `prisma db seed`?**
   - *Answer*: Command that runs a custom seed script (e.g. `prisma/seed.ts`) to populate the database with initial development data.

### Medium Questions
6. **Q: How does Prisma solve the N+1 Query Problem?**
   - *Answer*: The Rust Query Engine batches and optimizes nested `include` relations into single SQL queries using `IN` clauses or JOINs.
7. **Q: Compare Interactive Transactions vs Sequential Transactions in Prisma.**
   - *Answer*: Sequential (`prisma.$transaction([q1, q2])`) executes array of independent queries concurrently; Interactive (`prisma.$transaction(async (tx) => ...)`) passes a transaction client for dependent steps.
8. **Q: How do connection limits work with Prisma in serverless environments (Vercel/AWS Lambda)?**
   - *Answer*: Serverless functions spawn new containers per request, quickly exhausting PostgreSQL connection limits; solved by using Prisma Accelerate or PgBouncer connection poolers (`directUrl` vs `url`).
9. **Q: What is `@updatedAt` attribute in Prisma?**
   - *Answer*: Field attribute that automatically updates a `DateTime` field with current timestamp whenever the record is modified.
10. **Q: How do you create composite indexes in Prisma?**
    - *Answer*: Add `@@index([fieldA, fieldB])` block attribute inside the model definition.

### Advanced Questions
11. **Q: Walk through the architecture of the Prisma Rust Query Engine.**
    - *Answer*: The Node.js client sends query ASTs over IPC/engine protocol to the Rust binary, which plans, optimizes, builds SQL statements, executes against database connection pool, and returns serialized JSON.
12. **Q: How do you handle schema drift in production database deployments?**
    - *Answer*: Run `prisma migrate status` in CI/CD pipeline to verify pending migrations, apply using `prisma migrate deploy`, and avoid manual DDL changes outside Prisma migration files.
13. **Q: What is the performance impact of `include` vs `select` in Prisma queries?**
    - *Answer*: `include` fetches all scalar fields of parent model plus relation; `select` fetches strictly specified fields, reducing network payload size and database memory footprint.
14. **Q: How do soft deletes work in Prisma using extensions or middleware?**
    - *Answer*: Use Prisma Client Extensions (`prisma.$extends`) to intercept `delete` and `findMany` queries, converting `delete` to `update({ deletedAt: new Date() })` and injecting `deletedAt: null` into filters.
15. **Q: Explain how Prisma handles raw SQL queries with type safety (`$queryRaw`).**
    - *Answer*: `$queryRaw` uses tagged template literals (`prisma.$queryRaw\`SELECT * FROM users WHERE id = ${userId}\``) to safely parameterize inputs, preventing SQL injection while casting outputs to TypeScript types.
