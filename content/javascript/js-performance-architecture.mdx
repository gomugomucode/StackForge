# 1. Introduction

## Why This Matters
High-scale applications cannot rely on naive JavaScript execution assumptions. Understanding how the V8 engine compiles JavaScript code to machine instructions, how it allocates memory on the heap, and how its Garbage Collector operates empowers you to write code that optimizes for JIT compiler hot paths and avoids memory leaks under high throughput.

# 2. Core Concepts

## V8 Compilation Pipeline

```
+-------------------+
|  JS Source Code   |
+-------------------+
          |
          v
+-------------------+
|    AST Parser     |
+-------------------+
          |
          v
+-------------------+      Collect Type Feedback
| Ignition (Bytecode)-----------------------------+
+-------------------+                            |
          | (Hot Function?)                      v
          v                              +---------------+
+-------------------+                    | Type Feedback |
| TurboFan (JIT)    | <------------------| Vector (IC)   |
| (Machine Code)    |                    +---------------+
+-------------------+
          | (Type Check Failed / Deopt!)
          v
   Deoptimization 
 (Fall back to Ignition)
```

1. **Parser**: Converts source code into an Abstract Syntax Tree (AST).
2. **Ignition**: V8's bytecode interpreter that begins executing bytecode quickly without waiting for full compilation.
3. **TurboFan**: V8's optimizing JIT compiler. It takes hot functions along with type feedback and compiles them into ultra-fast machine code.
4. **Deoptimization**: If a assumption made by TurboFan fails (e.g. passing a string to a function that previously only received integers), TurboFan aborts and deoptimizes back to Ignition bytecode execution.

# 3. Hidden Classes & Inline Caching (IC)

## Hidden Classes (Shapes)
Because JavaScript is dynamically typed, V8 creates internal **Hidden Classes** (or Shapes) to track object property offsets in memory:

```javascript
// Good: Identical shape transition path -> Shares Hidden Class C0 -> C1 -> C2
function Point(x, y) {
  this.x = x; // Hidden Class transition C0 -> C1
  this.y = y; // Hidden Class transition C1 -> C2
}

const p1 = new Point(1, 2);
const p2 = new Point(3, 4); // Reuses existing C2 Hidden Class!
```

```javascript
// Bad: Out of order property initialization -> Creates divergent Hidden Class tree!
const p3 = {};
p3.x = 1;
p3.y = 2;

const p4 = {};
p4.y = 2; // Diverges!
p4.x = 1;
```

# 4. Garbage Collection Mechanics

V8 uses a **Generational Garbage Collector** based on the hypothesis that most objects die young.

1. **Young Generation (New Space)**:
   - Size: Small (1MB to 8MB).
   - Algorithm: **Scavenger (Cheney's copying algorithm)**.
   - Divides space into From-Space and To-Space; copies live objects during Minor GC ticks.
2. **Old Generation (Old Space)**:
   - Holds objects that survived two Minor GC cycles.
   - Algorithm: **Mark-Sweep-Compact**.
   - **Marking**: Tri-color marking algorithm traces live objects from roots.
   - **Sweeping**: Reclaims memory addresses of dead objects.
   - **Compacting**: De-fragments memory gaps to optimize pointer locality.

# 5. Interview Questions

### Beginner Questions
1. **Q: What is V8?**
   - *Answer*: Google's open-source C++ JavaScript and WebAssembly engine powering Chrome and Node.js.
2. **Q: What is JIT compilation?**
   - *Answer*: Just-In-Time compilation compiles bytecode into native machine code dynamically at runtime.
3. **Q: What is a Heap Snapshot?**
   - *Answer*: A diagnostic dump recording memory allocation of all active objects and retainers in V8 memory.
4. **Q: What is the Young Generation in V8?**
   - *Answer*: Memory space allocated for short-lived temporary objects managed by Scavenger GC.
5. **Q: What triggers a Minor GC?**
   - *Answer*: When allocation inside the New Space (From-Space) reaches capacity.

### Intermediate Questions
6. **Q: How do Hidden Classes improve property access speed?**
   - *Answer*: Hidden Classes store fixed memory offsets for properties, allowing V8 to access memory via direct pointer arithmetic rather than dictionary lookups.
7. **Q: What is Inline Caching (IC)?**
   - *Answer*: A technique where V8 remembers property memory offsets directly at invocation sites to bypass repeated Hidden Class lookups.
8. **Q: What causes V8 Deoptimization?**
   - *Answer*: Passing unexpected types or changing object shapes in hot functions previously optimized by TurboFan.
9. **Q: What is the generational hypothesis?**
   - *Answer*: The empirical observation that most allocated objects become unreachable shortly after instantiation.
10. **Q: Compare Monomorphic, Polymorphic, and Megamorphic calls.**
    - *Answer*: Monomorphic calls see 1 object shape (fastest JIT); Polymorphic calls see 2-4 shapes (slight lookup overhead); Megamorphic calls see 5+ shapes (falls back to slow dictionary lookup).

### Advanced Questions
11. **Q: Explain how V8 performs Concurrent & Incremental Marking in Old Space.**
    - *Answer*: V8 uses background worker threads to mark the object graph concurrently while JavaScript runs, using write barriers to catch pointers mutated during marking.
12. **Q: How does `delete obj.key` degrade V8 performance?**
    - *Answer*: `delete` alters object structure dynamically, converting fast vector-indexed properties to slow hash table dictionary mode and invalidating Hidden Classes.
13. **Q: How do you detect and fix memory leaks caused by detached DOM nodes?**
    - *Answer*: Take Chrome DevTools heap snapshots, filter by `Detached HTMLDivElement`, trace the retainer tree to locate variables holding references to detached DOM nodes, and clear references.
14. **Q: Describe Cheney's Copying Algorithm in Scavenger GC.**
    - *Answer*: Divides new space into From and To spaces. Scavenger copies active reachable objects from From to To space continuously, swapping spaces afterward and compacting memory.
15. **Q: How do array elements kinds (`PACKED_SMI`, `HOLEY_DOUBLE`, etc.) affect V8 optimization?**
    - *Answer*: V8 optimizes dense small integer arrays (`PACKED_SMI`) using raw machine arrays. Inserting a float or `undefined` permanently demotes the array's ElementKind down the chain, adding type checking overhead.
