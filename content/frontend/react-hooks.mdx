# 1. Introduction & Real Production Problem Statement

## Why React Hooks Architecture Matters
React 16.8 introduced **Hooks**, completely transforming component logic reuse. However, treating Hooks as magic functions without understanding their underlying **Fiber Linked List** architecture leads to infinite render loops, stale closure bugs, and severe memory leaks.

---

# 2. Core Concepts & Mental Model

## 1. Beginner Explanation
Hooks are special functions starting with `use` (e.g. `useState`, `useEffect`) that let function components attach state, lifecycle side-effects, and context values.

## 2. Intermediate Explanation & Fiber Linked List
React does NOT store hook state inside your function component. Instead, each React Fiber node maintains a singly linked list of **Hook Objects** attached to `fiber.memoizedState`.

```
FiberNode.memoizedState ---> [ Hook 1: useState ] 
                                   | next
                                   v
                             [ Hook 2: useEffect ] 
                                   | next
                                   v
                             [ Hook 3: useMemo ] ---> null
```

## 3. Senior Engineer Explanation & Rules of Hooks
Because Fiber relies on fixed linked list pointer traversal during re-renders, **Hooks MUST always be called in the exact same order on every render**. Calling hooks inside `if` conditionals or loops corrupts the linked list pointer index, resulting in cross-state corruption errors.

# 3. Code Examples & Custom Production Hooks

## Bad Code: Conditional Hook Invocation (Corrupts Fiber Linked List)

```typescript
// BAD: Invoking hook conditionally breaks Fiber linked list pointer order
function UserProfile({ userId }: { userId?: string }) {
  if (!userId) {
    return <div>No User</div>;
  }

  // CRASH ERROR: React Hook "useState" is called conditionally
  const [user, setUser] = useState(null);
  return <div>{user}</div>;
}
```

## Enterprise Production Pattern: Robust `useDebounce` Custom Hook

```typescript
import { useState, useEffect } from "react";

export function useDebounce<T>(value: T, delayMs: number = 300): T {
  const [debouncedValue, setDebouncedValue] = useState<T>(value);

  useEffect(() => {
    const handler = setTimeout(() => {
      setDebouncedValue(value);
    }, delayMs);

    return () => {
      clearTimeout(handler);
    };
  }, [value, delayMs]);

  return debouncedValue;
}
```

# 4. Debugging Guide & Common Anti-Patterns

## Fixing Infinite Render Loops in `useEffect`

```typescript
// BUG: Passing non-memoized object reference into useEffect dependency array
function DataFetcher() {
  const options = { timeout: 5000 }; // New object reference on EVERY render!

  useEffect(() => {
    fetchData(options);
  }, [options]); // Causes infinite re-render loop!
}

// FIX: Wrap object in useMemo or move inside effect
useEffect(() => {
  const options = { timeout: 5000 };
  fetchData(options);
}, []); // Stable dependency
```

# 5. Performance & Security Notes

## Performance Notes
- **`useMemo` / `useCallback` Overhead**: Do NOT wrap cheap primitive calculations in `useMemo`. The memory allocation of closure functions and dependency array comparison can cost more than re-running cheap functions.

## Security Notes
- **Data Validation**: Sanitize state variables updated via `useState` before passing to DOM innerHTML or external API payloads.

# 6. Interview Questions & Practice Exercises

### Q1: Why can't React Hooks be called inside `if` statements or loops?
- *Answer*: Fiber stores hook state in a sequential singly linked list on `fiber.memoizedState`. Conditional execution changes the invocation order, causing React to misassign state values to wrong hook pointers.

### Q2: How does `useRef` differ from `useState`?
- *Answer*: `useState` triggers a component re-render when its setter is called; `useRef` returns a mutable ref object (`{ current: T }`) whose changes persist across renders without triggering a re-render.
