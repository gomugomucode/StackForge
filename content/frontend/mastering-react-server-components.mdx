# 1. Introduction & Real Production Problem Statement

## Why React Server Components Architecture Matters
Traditional Client-Side Rendering (CSR) and Server-Side Rendering (SSR) require shipping massive JavaScript client bundles to the browser for interactive components.

**React Server Components (RSC)** introduce a fundamental paradigm shift: executing components exclusively on the server with **zero client JavaScript bundle size impact**, while streaming UI chunks progressively over a JSON-like binary format called the **React Flight Protocol**.

---

# 2. Core Concepts & Mental Model

## 1. Beginner Explanation
Server Components run ONLY on the server and render HTML/Flight AST payloads. They can directly query databases or access filesystem secrets without exposing code to the browser.

## 2. Intermediate Explanation & Flight Stream Protocol
Server Components do NOT render raw HTML strings like SSR. Instead, they compile UI trees into **Flight Data Streams**—a serialized string format describing the rendered component tree and placeholder slots for Client Components (`'use client'`).

```
0:["$","div",null,{"children":[["$","$L1",null,{}]]}]
1:I["./src/components/ClientCounter.tsx",["/static/chunks/app.js"],"default"]
```

## 3. Senior Engineer Explanation & Security Boundaries
RSC separates the module graph into **Server Module Graph** and **Client Module Graph**. Client Components act as leaf boundaries in the server tree. To prevent accidental leakage of sensitive server environment variables (e.g. database credentials) into Client Component props, React provides **Taint APIs** (`experimental_taintUniqueValue`).

# 3. Code Examples & Production Server Actions

## Enterprise Production Pattern: RSC Data Fetching with Server Action

```typescript
import { prisma } from "@/lib/prisma";
import { revalidateTag } from "next/cache";

// 1. Server Component: Direct DB query without API layer
export default async function UserDashboard({ userId }: { userId: string }) {
  const user = await prisma.user.findUnique({ where: { id: userId } });

  if (!user) return <div>User not found</div>;

  // 2. Inline Server Action for mutation
  async function updateBio(formData: FormData) {
    "use server";
    const bio = formData.get("bio") as string;
    await prisma.user.update({
      where: { id: userId },
      data: { bio },
    });
    revalidateTag(`user-${userId}`);
  }

  return (
    <div className="p-4 border rounded">
      <h1>{user.name}</h1>
      <form action={updateBio}>
        <input name="bio" defaultValue={user.bio || ""} />
        <button type="submit">Save Bio</button>
      </form>
    </div>
  );
}
```

# 5. Performance & Security Notes

## Performance Notes
- **Zero Bundle Size**: Dependencies imported inside Server Components (e.g. `marked`, `date-fns`, `prisma`) are executed on the server and omitted completely from client JS bundles.

## Security Notes
- **Taint Security API**: Protect secret API keys from leaking to client components using `import { taintUniqueValue } from 'react-server-dom-webpack/server'`.

# 6. Interview Questions & Practice Exercises

### Q1: Compare SSR vs RSC in Next.js App Router.
- *Answer*: SSR converts the whole page HTML on the server and sends a JS bundle to hydrate client components; RSC streams serialized Flight AST payloads for server nodes with zero client bundle overhead.

### Q2: What happens when a Client Component imports a Server Component?
- *Answer*: It is an anti-pattern. A Client Component cannot import a Server Component directly; instead, pass the Server Component as a `children` prop into the Client Component container.
